### 2026-10-10: M4-00 Fix the flaky language-switcher keyboard test at its cause
- Result: done
- Changes: `LanguageSwitcher.tsx`: the mirrored `isOpen` state and its `onToggle` handler are removed. Escape is now a React `onKeyDown` handler on the `<summary>` and on each language link, and outside taps are one document listener attached on mount. Both read `details.open` directly. `e2e/language-switcher.spec.ts`: a new regression test, "Escape closes a list that was opened before the page finished loading", and an explicit `untilInteractive(page)` precondition (`requestIdleCallback` after load) in the three tests of JavaScript-only behavior (keyboard, choosing the current language, tapping outside). No existing assertion was removed or changed (the diff is additions only).
- **Root cause (with evidence):** the switcher mirrored the native `<details>` open state into React state through `onToggle`, and attached its Escape and outside-tap listeners in an effect only while that state was true. When Enter opened the disclosure before React had hydrated, React never saw the `toggle` event, the state stayed `false` while the list was open, and the listeners never attached. Reproduction under 6× CPU throttling (Chrome DevTools protocol): 5 of 15 runs failed. In every failure, a second Escape pressed 2 seconds later, long after hydration, still did not close the list, which rules out mere timing and confirms the missing listener.
- **Second, smaller cause:** the test pressed keys before the page was interactive. With the state removed, the exact original test still failed 3–5 times in 30 under 6× throttling. A passive capture-phase recorder showed React's root attached but the switcher not yet hydrated (or hydrated but not committed) when Escape arrived; React does not replay these root-level events. No client code can handle a key before hydration finishes, while the native disclosure keeps working, so the test now waits explicitly until the page is idle before testing JavaScript-only behavior.
- Verification: the new regression test passes with the fix and fails with the old component (6 of 6 runs each way): it holds the page's scripts, opens the list by keyboard natively, releases the scripts, and expects Escape to close it. The exact original test passed **50 of 50** runs under 6× CPU throttling with the precondition (temporary probe, deleted). `playwright test e2e/language-switcher.spec.ts --repeat-each=50` (task validation): **1100 passed**, i.e. 11 tests × 2 projects × 50, including the keyboard test and the new test 100 times each. `pnpm check` (web 34, api 16), `pnpm build`, `DATABASE_URL=<local> pnpm test:e2e` (api 16, web 244) pass.
- Versions / choices: a React `onKeyDown` on the `<details>` itself was tried first, but `jsx-a11y/no-noninteractive-element-interactions` rejects it (lint is not weakened), so the handler sits on the focusable `<summary>` and links. Next.js only sets `window.__NEXT_HYDRATED` in its internal test mode, so "interactive" is detected with `requestIdleCallback`, which runs once hydration's scheduled work has drained. Blast radius: no other component mirrors DOM state through effects (`useState`, `onToggle`, `addEventListener` were searched in `apps/web/src`).
- Notes: On a slow phone, Escape or an outside tap in the first moments before hydration still does nothing; the list then closes with the button, as without JavaScript.
